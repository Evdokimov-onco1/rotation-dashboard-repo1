# Первичная настройка и деплой на Timeweb

Пошаговая инструкция по разделу 9 ТЗ. Делается **один раз**; дальше любое обновление —
это просто пуш в `main` (GitHub Actions собирёт и выложит сам, данные в БД не трогаются).

В примерах:
- `ЛОГИН` — логин хостинга Timeweb (вида `cw12345`);
- поддомен — `rotation.mmcc-education.ru` (финальное имя — на ваше усмотрение);
- пути на хостинге Timeweb обычно выглядят как `/home/c/ЛОГИН/...` — точные значения
  видно в панели и по SSH командой `pwd`.

Что получится в итоге:

```
/home/c/ЛОГИН/
├── rotation.mmcc-education.ru/
│   └── public_html/            ← webroot: статика фронтенда + api/  (заливает Actions)
├── rotation-backend/            ← backend/ и data/ вне webroot       (заливает Actions)
│   ├── backend/  (notify.php, scripts/, api/…)
│   └── data/     (seed.json)
├── rotation-config.php          ← реквизиты MySQL (создаёте вручную, в git не попадает)
└── backups/                     ← еженедельные дампы БД (cron)
```

---

## 1. Поддомен, PHP и SSL

1. Панель Timeweb → **«Домены и поддомены»** → у домена `mmcc-education.ru` нажать
   **«Добавить поддомен»** → имя `rotation`. Каталог сайта создастся автоматически.
2. Раздел **«Сайты»** (или настройки поддомена) → версия PHP — **8.2**.
3. Раздел **«SSL-сертификаты»** → выпустить бесплатный **Let's Encrypt** для
   `rotation.mmcc-education.ru`. Редирект HTTP→HTTPS дополнительно включать не нужно —
   его делает `.htaccess` из деплоя (но если в панели есть галочка — можно включить и её).

## 2. База данных MySQL

1. Панель → **«Базы данных MySQL»** → **«Создать базу»**: имя вида `ЛОГИН_rotation`,
   пользователь и пароль запишите.
2. Хост БД — `localhost` (стандарт для Timeweb).

## 3. Файл с реквизитами БД (вне webroot)

Через **файловый менеджер** панели (или по SSH) создайте файл
`/home/c/ЛОГИН/rotation-config.php` — на уровень ВЫШЕ каталога поддомена, чтобы он
не был доступен по URL:

```php
<?php
return [
    'dsn'     => 'mysql:host=localhost;dbname=ЛОГИН_rotation;charset=utf8mb4',
    'db_user' => 'ЛОГИН_rotation',
    'db_pass' => 'ПАРОЛЬ_ИЗ_ШАГА_2',
    'notify_log' => '/home/c/ЛОГИН/rotation-backend/notify.log',
];
```

Backend ищет конфиг сам: для веб-запросов — «каталог над webroot'ом /
`rotation-config.php`», для cron-скриптов путь передаётся переменной `ROTATION_CONFIG`
(см. шаг 8). Образец файла — `backend/config.sample.php`.

## 4. SSH-доступ и ключ для деплоя

1. Панель → **«SSH»** → включить SSH-доступ (если ещё не включён), узнать хост и порт
   (обычно `ЛОГИН.timeweb.ru`, порт 22).
2. На **своём компьютере** сгенерируйте пару ключей (Enter на все вопросы):
   ```bash
   ssh-keygen -t ed25519 -f ~/.ssh/timeweb_deploy -N ""
   ```
3. Добавьте **публичный** ключ на хостинг:
   ```bash
   ssh-copy-id -i ~/.ssh/timeweb_deploy.pub ЛОГИН@ЛОГИН.timeweb.ru
   # или вручную: дописать содержимое timeweb_deploy.pub в ~/.ssh/authorized_keys на хостинге
   ```
4. Проверьте вход без пароля: `ssh -i ~/.ssh/timeweb_deploy ЛОГИН@ЛОГИН.timeweb.ru` →
   `pwd` покажет домашний каталог (пригодится для секретов ниже). Там же создайте каталог
   backend'а: `mkdir -p ~/rotation-backend ~/backups`.

## 5. Секреты GitHub

GitHub → репозиторий → **Settings → Secrets and variables → Actions →
New repository secret**. Нужны шесть секретов:

| Секрет | Значение (пример) |
|---|---|
| `DEPLOY_HOST` | `ЛОГИН.timeweb.ru` |
| `DEPLOY_PORT` | `22` |
| `DEPLOY_USER` | `ЛОГИН` |
| `DEPLOY_SSH_KEY` | содержимое **приватного** файла `~/.ssh/timeweb_deploy` целиком, со строками BEGIN/END |
| `DEPLOY_WEBROOT` | `/home/c/ЛОГИН/rotation.mmcc-education.ru/public_html` |
| `DEPLOY_BACKEND_DIR` | `/home/c/ЛОГИН/rotation-backend` |

⚠️ Деплой выполняет `rsync --delete`: содержимое webroot'а поддомена будет приводиться
в точное соответствие сборке — ничего постороннего в этот каталог руками не кладите.

## 6. Первый деплой

GitHub → вкладка **Actions** → workflow **Deploy** → **Run workflow** (кнопка справа),
либо просто смержить PR в `main`. Зелёная галочка = статика и API на хостинге.
Сайт уже откроется, но покажет ошибку БД — она пуста, идём дальше.

## 7. Инициализация БД и установка PIN

По SSH на хостинге (PIN придумайте свой — это код администратора и учебной части):

```bash
cd ~/rotation-backend
ROTATION_CONFIG=~/rotation-config.php php backend/scripts/init_db.php \
    --seed=data/seed.json --pin=ВАШ_PIN
```

Скрипт создаст таблицы, зальёт график из `seed.json` (58 блоков) и сохранит хэш PIN.
Откройте сайт — матрица должна полностью совпадать с Приложением В ТЗ.

## 8. Crontab

Панель → **«Crontab»** → добавить две задачи (время сервера Timeweb — московское;
если у вашего тарифа иное, сдвиньте часы):

**Напоминания кураторам — будни, 7:00** (этап 1 — сухой прогон в `notify.log`):

```
0 7 * * 1-5  ROTATION_CONFIG=/home/c/ЛОГИН/rotation-config.php php /home/c/ЛОГИН/rotation-backend/backend/notify.php
```

**Резервная копия БД — воскресенье, 3:00** (хранится 8 недель):

```
0 3 * * 0  mysqldump -uЛОГИН_rotation -p'ПАРОЛЬ' ЛОГИН_rotation | gzip > /home/c/ЛОГИН/backups/rotation-$(date +\%F).sql.gz && find /home/c/ЛОГИН/backups -name 'rotation-*.sql.gz' -mtime +56 -delete
```

Восстановление из копии: `zcat rotation-ДАТА.sql.gz | mysql -u... -p... ЛОГИН_rotation`.

## 9. Проверка (критерии приёмки этапа 1)

1. `https://rotation.mmcc-education.ru` открывается по HTTPS, матрица читаема на 1366×768.
2. График совпадает с Приложением В (у Шидаевой недели 13–16 — ОО №2).
3. Кабинет куратора: выбрать заведующего — секции «сейчас / придут / завершились недавно»;
   у кандидатов ЦАОП — «возможно, ваши».
4. Админка: без PIN редактирование недоступно (в т.ч. прямым запросом к API);
   после PIN — назначение куратора сразу убирает ⚠️ в матрице.
5. Попытка сохранить пересекающиеся блоки — понятная ошибка, сохранение отклонено.
6. Правка видна с другого компьютера и после перезагрузки; каждая правка — в «Журнале правок».
7. Учебная часть: PIN → счётчики и задачи дня по кураторам.
8. На следующее утро в `~/rotation-backend/notify.log` появилась запись сухого прогона.

## 10. Эксплуатация

- **Обновление кода:** пуш в `main` → Actions развернёт сам. БД не затрагивается.
- **Смена учебного года:** положить новый `data/seed.json`, затем по SSH
  `init_db.php --seed=data/seed.json --force` (перед этим сделать копию БД — шаг 8).
- **Этап 2 (Telegram):** создать бота у @BotFather, токен записать в `settings`
  (`telegram_bot_token`), привязать `telegram_chat_id` кураторам — код рассылки уже
  боевой, ничего перекладывать не нужно.
- **Запасной путь без Actions:** по SSH `git clone` репозитория и ручной `rsync` тех же
  каталогов (см. `.github/workflows/deploy.yml` — там видно, что куда кладётся).
