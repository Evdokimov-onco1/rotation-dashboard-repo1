# Техническое задание: Дашборд ротаций ординаторов ММКЦ «Коммунарка»

**Версия:** 1.3 · **Дата:** 14.09.2026 · **Для реализации в:** Claude Code

Изменения 1.3 относительно 1.2 (по анкете заказчика 14.09.2026): учебные годы и архив; две
организации (ММКЦ и НМХЦ им. Пирогова) и роль «распорядитель когорты»; второй год обучения
с закреплением за отделением; генератор ротации с приоритетами и порогом загрузки;
календарь года с правкой недель и дней; вход по логину и паролю вместо общего PIN;
реальные данные вынесены из репозитория. Telegram-рассылка перенесена на этап 3.

## 1. Цель и контекст

Ординаторы проходят ротации по подразделениям онкологического центра блоками по 2–6 недель.
Логбук ординатора подписывается куратором **за каждый день посещения**; в последние дни блока
куратор должен доподписать все дни и сообщить ординатору, куда тот направляется дальше.
Сайт решает: (1) кураторам неудобно отслеживать по общей Excel-таблице, кто у них ротируется и
чей логбук пора подписать; (2) для подразделений ЦАОП куратор назначается вручную из нескольких
кандидатов; (3) расписание меняется в течение года и правится без пересборки сайта; (4) **с 1.3** —
график нового учебного года строится автоматически по правилам, а не руками в Excel.

Учебный год 2026/27: **29 ординаторов** — 18 первого года (15 ММКЦ и 3 НМХЦ) на ротации по
графику и 11 второго года (8 ММКЦ и 3 НМХЦ), закреплённых за отделениями на весь год. Старт
15.09.2026. Год 2025/26 (8 ординаторов, завершён) хранится как архив.

## 2. Роли и сценарии

**Куратор (заведующий)** — без авторизации. Открывает «Кабинет куратора», выбирает своё ФИО,
видит: кто сейчас на ротации, кто завершает (подписать логбук), кто придёт, «возможно ваши».

**Учебная часть** (роль `admin`) — вход по логину и паролю. Всё: график любой организации,
календарь года, ординаторы, пользователи, настройки, генератор, журнал.

**Распорядитель когорты** (роль `dispatcher`, привязан к организации) — вход по логину и паролю.
Строит и правит график **только ординаторов своей организации**: генератор, блоки, назначение
кураторов, состав ординаторов. Видит всё остальное в режиме просмотра. Распорядители: по НМХЦ —
Евдокимов В.И., по ММКЦ — Петухов Е.А. (он же куратор лучевой терапии).

**Гость** — просмотр матрицы, календаря и кабинета куратора без редактирования.

## 3. Модель данных

**academic_years** — учебные годы: `id` (`2026-27`), `label`, `date_start`, `date_end`,
`is_current`, `note`. Один год — текущий, открывается по умолчанию; остальные — архив,
доступны через переключатель в шапке.

**organizations** — `mmcc` ММКЦ «Коммунарка», `nmhc` НМХЦ им. Пирогова.

**residents** — `id`, `year_id`, `org_id`, `fio`, `year` (год обучения), `mode`
(`rotation` — блоки строит генератор; `fixed` — закреплён за отделением, блоки любой длины
вручную), `priority` (текст из анкеты: ХТ, ЛТ, маммология…), `email`, `phone` (на этап 3),
`active`. Один человек в разных учебных годах — разные записи.

**weeks** — календарь недель года: `year_id`, `num`, `date_start`, `date_end`, **`is_rotation`**
(неделя учебная, но ротации нет — остаётся в нумерации, не считается в длине блоков и не даёт
дней для подписи), `note`.

**calendar_overrides** — исключения по дням: `year_id`, `date_from`, `date_to`, `kind`
(`off` — ротации нет: праздник, сессия; `on` — ротация идёт: рабочая суббота), `note`.
Приоритет выше флага недели и выходных.

**units**, **curators**, **unit_curators** — как в 1.2 (справочник общий для всех лет).

**rotation_blocks** — `id`, `year_id`, `resident_id`, `unit_id`, `week_from`, `week_to`,
`assigned_curator_id`, `comment`. Блок может проходить через неделю без ротации.

**users** — `login`, `password_hash`, `display_name`, `role` (`admin`|`dispatcher`), `org_id`,
`active`. **login_attempts** — защита от перебора.

**audit_log** — `ts`, `user_login`, `year_id`, `action`, `block_id`, `old_value`, `new_value`.

**settings** — `capacity_threshold` (порог загрузки, по умолчанию 3), окна напоминаний,
`program_json` (программа генератора, пусто = по умолчанию), токен бота (этап 3).

Правила целостности: блоки одного ординатора не пересекаются; недели существуют в календаре
года; ординатор принадлежит году блока; распорядитель меняет только свою организацию.

### 3.1. День ротации

Единая функция (сервер `calendar.php`, клиент `lib/calendar.ts`):
1) попадает в исключение по дням → `off` = нет, `on` = да; 2) суббота/воскресенье → нет;
3) внутри недели с `is_rotation` → да; иначе нет. Первый/последний день блока, окна «2 последних
дня» и «3 дня до приёма», рассылка — считаются по дням ротации.

## 5. Интерфейс

Дизайн — развитие утверждённого прототипа (`docs/prototype-demo.html`). Шапка: штамп текущей
недели, название с учебным годом, **переключатель года**, сегодняшняя дата; при просмотре
архива — жёлтая полоса «Вы смотрите архив».

### 5.1. Кабинет куратора
Как в 1.2. У ординатора показывается организация и год обучения. Блоки неактивных ординаторов
не показываются. «Возможно, ваши» — только незавершённые блоки.

### 5.1а. Кабинет ординатора (добавлено 15.09.2026)
Вкладка «Кабинет ординатора», без авторизации. Ординатор выбирает себя и видит личный план на
год: все блоки по порядку с подразделением, корпусом, неделями и датами, куратором (или красной
пометкой «куратор ещё не назначен»), статусом «завершена / сейчас, до … / с …». Справа — год по
неделям в цветах подразделений с отметкой текущей недели, счётчики «пройдено блоков» и «недель до
конца года», карточки «Сейчас» и «Дальше». Постоянная ссылка вида `…/#r=<id>` для закладки; у
кабинета заведующего аналогичная `…/#c=<id>`.

### 5.2. Матрица
Строки сгруппированы: **организация × год обучения** (заголовок группы с числом человек).
Фильтры: организация, год обучения. Закреплённые (`fixed`) помечены 📌. Недели без ротации —
штриховка в шапке и пустых ячейках. Под матрицей — **таблица загрузки**: подразделение × неделя,
число ординаторов; значения выше порога — жёлтым. Клик по блоку — карточка; после входа —
редактор, если блок относится к организации пользователя.

### 5.3. Календарь (новая вкладка)
Список недель года: № , даты, флажок «ротация идёт», примечание; кнопка «Сохранить недели».
Список исключений по дням с добавлением (с даты, по дату, тип, примечание) и удалением.
Правка — только учебная часть; остальные видят календарь для справки.

### 5.4. Кабинет учебной части
Как в 1.2, вход по логину и паролю (любая роль). Окна считаются по дням ротации.

### 5.5. Админка
Вход по логину и паролю. Показывает, кто вошёл и с каким охватом. Разделы:
- **Генератор ротации** (5.6): когорта (распорядитель — только своя), «пересобрать с недели»,
  кнопка «Сгенерировать» → предпросмотр (блоки по ординаторам, предупреждения, сумма превышений
  порога), «Другой вариант», «Применить». Применение заменяет блоки выбранных ординаторов с
  указанной недели, более ранние блоки сохраняются. Прошедшее правится вручную.
- **Загрузка выше порога** — справочный список отрезков «подразделение, недели, человек».
- **Требуют назначения куратора** — manual-блоки без куратора в охвате пользователя.
- **Ординаторы** — список с правкой (ФИО, организация, год, режим, приоритет, активен) и
  добавлением; распорядитель — только своя организация.
- **Пользователи** (только admin) — логины, роли, организация, смена пароля, отключение.
- **Настройки** (только admin) — порог загрузки, текущий учебный год.
- Журнал правок с именем пользователя; «+ Добавить блок»; «Выйти».

### 5.6. Генератор ротации
Программа первого года (по графику 2025/26, `program_json` в настройках):
- **ЦАОП** — 1 блок по 6 недель (ЦАОП г/м/у или ЦАОП общий; профиль по приоритету);
- **длинные** — 2 из 3 по 6 недель: ХТ ДС (С8), ЛТ, ООПЛТ;
- **онкоотделения** — 4 из 5 по 4 недели: ОО №1–№5;
- при остатке недель — короткий блок ЛД/иУЗИ (2 недели) или удлинение последнего блока.

Правила:
- **Приоритет** задаёт первый блок и профиль ЦАОП: ХТ → ХТ ДС; ЛТ → ЛТ; ХТ+ЛТ → ХТ ДС, затем ЛТ;
  абдоминальная хирургия и хирургия → ОО №2; маммология → ОО №1 и ЦАОП г/м/у; НЭО → ХТ ДС;
  «не известно» — без приоритета. Остальные — ЦАОП общий онколог.
- **НМХЦ, первый год** — первый блок в одном из ЦАОП: ЦАОП г/м/у, ЦАОП общий, ХТ ДС А22
  (ЦАОП-химиотерапия), каждому свой, по кругу со случайного старта.
- Порядок остальных категорий — сдвинутый для каждого ординатора шаблон
  (ОО · длинный · ОО · ЦАОП · ОО · длинный · ОО), чтобы длинные блоки не собирались у всех в конце
  года; конкретное подразделение внутри категории — с наименьшей загрузкой относительно целевой.
- **Порог загрузки** (настройка, по умолчанию 3 = округлённое среднее 29 ординаторов /
  12 подразделений) — только предупреждение, генерацию и ручные правки не блокирует.
  Auto-подразделениям куратор проставляется, manual — остаются «⚠ не назначен».
- Второй год (`fixed`) генератором не трогается: один блок на весь год, правится вручную.
- Результат воспроизводим по номеру варианта (seed). Консоль: `backend/scripts/generate.php`.

Известное ограничение: три длинных подразделения при 18 первогодках и 4 второгодках в ЛТ
структурно держат 4–5 человек одновременно (нижняя граница превышения порога ≈ 146
человеко-недель); генератор минимизирует превышение, но не может его убрать без изменения
программы (например, 1 длинный блок вместо 2) или порога.

## 7. Архитектура и API

Стек без изменений: React 18 + TypeScript + Vite + Tailwind + shadcn/ui; PHP 8.2 без фреймворков;
MySQL на Timeweb (локально SQLite); GitHub Actions → rsync по SSH.

Маршруты (`api/index.php`):
- `GET /api/schedule[?year=ID]` — год, список лет, недели с флагом, исключения, организации,
  подразделения, кураторы, ординаторы, блоки, окна, порог, текущий пользователь.
- `GET /api/curators/{id}/dashboard[?year=]`.
- `POST /api/auth/login {login,password}` · `POST /api/auth/logout` · `GET /api/auth/status`.
- `POST /api/blocks` · `PUT|DELETE /api/blocks/{id}` · `PUT /api/blocks/{id}/curator` ·
  `POST /api/blocks/bulk {yearId, residentIds, fromWeek, blocks}` (транзакция, та же валидация).
- `POST /api/generate {yearId, orgId?, residentIds?, fromWeek, seed?}` — предпросмотр.
- `POST /api/residents` · `PUT /api/residents/{id}`.
- `PUT /api/years/{id}/weeks` · `POST /api/years/{id}/overrides` · `DELETE /api/overrides/{id}` ·
  `PUT /api/years/{id}/current` — только admin.
- `GET|POST /api/users` · `PUT /api/users/{id}` · `PUT /api/settings` — только admin.
- `GET /api/audit[?year=]` — по сессии.

Права проверяются на сервере: изменяющие запросы без сессии → 401; чужая организация → 403;
admin-маршруты для распорядителя → 403.

## 8. Безопасность и доступ

- Просмотр публичный (ФИО ординаторов и заведующих, график).
- Вход: логин + пароль (`password_hash`), httpOnly-cookie SameSite=Lax, проверка Origin у
  изменяющих запросов, не более 5 неудачных попыток за 15 минут с IP. Пароль не короче 6 символов.
- Учётные записи создаёт учебная часть (админка или `backend/scripts/user.php`); первый
  администратор — `init_db.php --admin=login:пароль`.
- Реальные данные — вне репозитория и вне webroot; файл БД/реквизиты — вне webroot.
