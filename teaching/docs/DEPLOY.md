# Публикация изолированного пилота

Ротации обслуживаются своим приложением и MySQL. Модуль нагрузки размещается только в отдельном каталоге `/teaching-preview/` с отдельной SQLite. На общем тарифе нельзя обещать изоляцию вычислительных ресурсов; здесь изолированы файлы, данные, сессия и маршруты.

## Перед публикацией

1. Запустить проверки из `../README.md` и сборку `scripts/package.py`.
2. Убедиться, что workflow ротаций исключает `/teaching-preview/` и `/teaching/` из `rsync --delete`.
3. Сохранить контрольные суммы действующего сайта вне нового каталога и проверить доступность `/` и `/api/schedule`. Рабочую БД не менять.
4. Проверить тариф, PHP 8.2, PDO SQLite, ZipArchive, DOM/XML, mbstring. Использовать известный SSH host key; не отключать проверку хоста.
5. При обновлении сохранить предыдущий код и согласованную резервную копию SQLite (SQLite backup/VACUUM INTO; простое копирование активного WAL недостаточно), оригиналы импорта и отчёты. Резервные копии хранить вне webroot с правами 0700/0600.

## Особенность Timeweb

Проверка 25.10.2026 показала: Nginx отдаёт `.txt` и `.docx` в обход Apache, даже из скрытого каталога с `Require all denied`. PHP вне webroot получает Permission denied при совпадающем владельце. Поэтому **никакие конфиденциальные `.xlsx`, `.docx`, `.json`, `.txt` не размещаются как обычные статические файлы в webroot**. Оригиналы и отчёты хранятся с суффиксом `.blob`, шаблон — `.docx.blob`; эти запросы проходят через Apache и блокируются. SQLite и файлы сессий также проверяются по HTTP. Имя `.docx` присваивается только авторизованной API-выгрузке. Нельзя считать наличие `.htaccess` доказательством защиты: до данных и после каждого изменения размещения проверять фактические коды для всех типов хранения.

## Раскладка

```text
teaching-preview/
  index.php, assets/, api.php, .htaccess
  _app/                  # backend, schema, scripts, пустой бланк; HTTP запрещён
  _private/              # HTTP запрещён; 0700
    .htaccess            # Require all denied
    config.php           # config.example.php с путями этой среды
    teaching.sqlite      # 0600, отдельная база
    sessions/, imports/, reports/
```

Пакет `.release/` не содержит `_private`. Загружать его только в заранее проверенный каталог `.../public_html/teaching-preview/`, никогда в корень ротаций. При обновлении кода использовать `rsync --delete --exclude '/_private/'` **только внутри каталога модуля**. Начальное создание `_private` выполняется отдельно. Резервная копия обязательна до последующей замены кода.

До загрузки данных положить защитные `.htaccess` и безвредный проверочный файл; получить HTTP 403 для `_private/` и `_app/`. После этого загрузить конфиг и приватный JSON-сид, выполнить CLI:

```bash
php _app/scripts/provision.php _private/config.php _private/seed.blob
php _app/scripts/import.php _private/config.php _private/input.blob --preview source.xlsx
# Только после проверки отсутствия ошибок и ожидаемых сумм:
php _app/scripts/import.php _private/config.php _private/input.blob --commit source.xlsx
```

Сид содержит `teachers: [{id,name,rate}]`, `groups: [{id,course,semester,label}]` и `users: [{login,password,name,roles,teacher_id?}]`. Пароли уникальные, случайные, минимум 16 символов; в БД сохраняются хэши. Сид с открытыми паролями удалить после инициализации. Импорт архивирует оригинал в защищённом каталоге; временный `input.blob` можно убрать после проверки копии. Не переносить локальную тестовую БД с демонстрационным фактом.

## Приёмка на хостинге

- HTTPS, отдельный cookie `TEACHINGPREVIEWSESS`, `Secure`, `HttpOnly`, `SameSite=Strict`, путь `/teaching-preview/`.
- Без входа bootstrap не содержит фамилий и часов; изменение без CSRF запрещено.
- `_private/config.php`, `_private/teaching.sqlite`, `_app/backend/Service.php`, импорт и DOCX напрямую дают 403. Авторизованная выгрузка идёт только через API.
- Начальные плановые суммы совпадают с оригиналом; факт и расписания пусты.
- Проверить вход каждой роли, собственную область преподавателя, создание проекта DOCX и браузерный интерфейс.
- Повторить контрольные суммы старого сайта и проверить его доступность. Различий в коде/конфиге ротаций быть не должно.

## Откат

Не менять домен, корень, конфиг или MySQL ротаций. Отключить только `/teaching-preview/` ответом 503, сохранить текущие данные, вернуть предыдущий пакет кода. Восстановление БД допустимо только с осознанной сверкой появившихся после копии записей: нельзя молча терять работу пользователей. Для первого тестового размещения остановка нового каталога полностью выключает модуль; ротации продолжают работать.

Автоматического деплоя модуля из основной ветки нет. Слияние PR не является разрешением включать модуль в рабочую эксплуатацию.
